# BOSS 直聘 Windows 客户端自动邀约助手

这是一个 Windows 单机版、纯 Python 的招聘邀约辅助工具。它连接用户已经打开并登录的 BOSS 直聘 Windows 客户端，通过 Windows UI Automation 读取可访问性控件，不使用固定屏幕坐标。

项目默认是测试模式：`config.json` 中的 `"dry_run": true` 会让程序只识别、筛选和记录匹配候选人，绝不点击沟通按钮，也不会填写或发送消息。只有用户手工改成 `false`，并在软件中再次确认，才可能进入正式发送流程。

## 功能范围

- 连接已经运行的 `boss-zhipin.exe`，用户自行登录并进入“推荐”或“搜索”候选人页；
- 识别带有“打招呼”“立即沟通”或“聊一聊”明确动作的候选人卡片；
- 按包含/排除关键词做简单筛选；
- 从稳定控件 ID、姓名/岗位/公司等稳定字段生成候选人 key；
- 使用 SQLite 记录 `dry_run_match`、`sent`、`filtered`、`duplicate`、`failed`、`greeting_unverified`、`manual_skip`；
- 正式阶段只点击一次 BOSS 原生“打招呼”，由 BOSS 根据当前岗位生成默认招呼，不追加第二条消息；
- 通过“已向牛人发送招呼”提示或同一卡片变为“继续沟通”验证成功；
- 识别“沟通权益不足/去充值”等平台拒绝提示，记录为失败并暂停，不冒充发送成功；
- 仅将已验证的 `sent` 计入每日发送数量；
- 面板可编辑并保存面试邀约回复话术；用户手动打开目标聊天后，可由程序填写、点击明确发送按钮并验证结果；
- 面板提供“自动回复话术库”区域，按 `关键词1|关键词2 => 已批准回复` 自动解析；
- 用户每次启动后必须本人点击“开启自动回复”，程序才会进入消息页并轮询全部可识别的未读会话；
- 未读列表通过独立未读数字识别；带 `[已读]`/`[送达]` 的己方末条消息不会被当作来信；
- 未读预览命中话术后，程序会打开精确会话、读取完整聊天，并通过无障碍语义和消息气泡相对位置区分来信/己方消息；复核不一致时不回复；
- 测试模式下“回复当前会话”只预检唯一输入框和发送按钮，不填写、不点击、不发送；
- 支持连接、页面诊断、开始/继续、暂停、停止和紧急停止；
- 可配置打开助手后自动连接并开始运行；正式模式每次启动仍会显示一次发送确认；
- 支持 BOSS 当前的无限滚动列表：已加载卡片处理完后自动下拉并等待新候选人；
- 发送间隔、批次暂停、每日上限和连续失败停止；
- 默认每次验证成功后等待 5 秒再处理下一人；每日上限仍优先于发送速度；
- 面板显示今日已沟通人数、验证成功发送人数、待人工核对数、当前 BOSS 未读消息数和本次运行统计；
- 风险关键词检测、异常截图、滚动日志和单实例锁；
- 自动关闭已知的普通信息浮层；不识别的弹窗仍会暂停等待人工核对；
- PyInstaller 目录版、ZIP 便携包和 Windows `BossInviter-Setup.exe` 安装程序输出。

这些节流配置用于正常操作节奏和防止误操作，不是“防封”措施。每日上限按“验证成功 + 发送结果待核对”共同计算，未知结果也会占用名额，避免潜在已发送动作造成超量。

## 明确不支持

本项目不绕过验证码或安全验证，不自动处理风控，不伪装浏览器/设备指纹，不轮换代理，不盗取 Cookie，不调用未经授权的接口，不隐藏自动化特征，不模拟鼠标抖动，不无限群发，也不得在候选人明确拒绝后继续发送。

软件检测到验证码、安全验证、操作频繁、账号异常或其他配置中的风险文字后会截图并停止。所有验证和账号操作必须由用户本人完成。

## 系统要求

- Windows 10/11 64 位；
- BOSS 直聘 Windows 客户端，进程名通常为 `boss-zhipin.exe`；
- 源码运行需要 Python 3.11 或 3.12；
- BOSS 客户端与本助手应使用相同 Windows 权限级别。通常都以普通用户运行，不要将其中一个单独以管理员运行。

## 安装与启动

安装包方式（分享给朋友时推荐）：

1. 双击 `BossInviter-Setup.exe`。
2. 安装完成后从桌面或开始菜单启动 `BossInviter`。
3. 首次启动默认为测试模式，不会真实发送；先登录自己的 BOSS 客户端并检查页面识别。
4. 可以在主面板直接修改“本次邀约人数、发送间隔、每日最大发送人数”和面试邀约回复话术并保存。

源码方式：

1. 安装 Python 3.11/3.12，安装时勾选 `Add Python to PATH`。
2. 双击 `install.bat`，它会创建 `.venv` 并安装依赖。
3. 手动启动 BOSS 直聘客户端并登录。
4. 双击 `run.bat`。
5. 默认配置下，在助手中点击“连接 BOSS 客户端”。
6. 先进入候选人页，点击“页面诊断”，确认能识别卡片。
7. 保持测试模式，点击“开始/继续”。

将 `auto_start` 设为 `true` 后，只要 BOSS 客户端已经登录，打开助手就会自动连接、进入推荐页并开始处理；`auto_scroll=true` 会在当前卡片处理完后自动滚动加载更多。若 `dry_run=false`，每次打开助手仍会弹出一次真实发送确认，确认后程序才会自行连续运行，不需要 Codex 在线控制电脑。

命令行等价命令：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

## 新版界面与推荐使用顺序

软件左侧只保留五个入口，所有按钮都是程序本身的功能，不需要 Codex 远程操作鼠标：

1. **运行面板**：设置本次人数、发送间隔和每日上限，连接 BOSS 客户端后启动、暂停或停止任务。
2. **筛选设置**：按需填写关键词、城市、期望薪资。三个类别全部留空时不筛选，直接执行自动打招呼；填写多个关键词或城市时各自命中任意一个即可，已填写的不同类别必须同时满足。
3. **自动回复**：默认只显示允许开关和“我的话术”列表。新增、编辑、删除均使用结构化弹窗；“防误发与次数限制”和“测试一条来信”默认折叠，需要时再展开。
4. **数据统计**：查看今日沟通、成功发送、自动回复、待人工核对、当前未读和本次运行结果。
5. **运行日志**：查看跳过、失败、暂停原因，并可打开日志或截图目录。

薪资统一按 `K/月` 填写，例如最低 `10`、最高 `20`。设置了薪资条件但候选人卡片没有可识别薪资时，程序会跳过并记录原因，不会猜测。点击“清空筛选”后还需点击“保存筛选设置”才会生效。

自动回复只发送已启用且唯一命中的固定话术。停止联系词、没有匹配、同时命中不同回复、消息方向不明确、达到次数限制或发送前会话发生变化时均不会自动发送。测试一条来信只显示匹配结果，绝不连接平台或发送消息。

## 首次测试与页面诊断

首次使用不要修改 `dry_run`。打开客户端并进入候选人推荐/搜索结果后：

1. 点击“连接 BOSS 客户端”；
2. 点击“页面诊断”；
3. 在界面日志或 `logs/boss_inviter.log` 中检查窗口标题、进程 ID、可见按钮、控件类型数量、沟通文字匹配数和候选人识别数；
4. 查看 `screenshots/desktop_diagnostic_*.png`；
5. 若需要更详细的脱敏控件树，把 `diagnostics_save_tree` 改成 `true`，重新启动后诊断。JSON 会写入 `screenshots/`，手机号和邮箱会脱敏。

诊断模式只读取控件和截图，绝不发送消息。

若 GUI 无法打开，可在命令行执行一次性只读诊断：

```powershell
BossInviter.exe --diagnose-once
```

结果写入 `logs/diagnose_once.json`，截图写入 `screenshots/`。

## 配置说明

程序只读取 `config.json`，运行时不会覆盖它。`config.example.json` 是安全模板。

| 字段 | 含义 |
| --- | --- |
| `control_mode` | 当前固定为 `desktop` |
| `dry_run` | `true` 为测试模式；默认值且最安全 |
| `message` | “回复当前会话”使用的面试邀约话术；原生打招呼阶段不会追加这条消息，不能为空 |
| `auto_reply.enabled` | 是否允许使用话术库；即使为 `true`，每次启动仍需本人点击“开启自动回复” |
| `auto_reply.poll_seconds` | 全消息页未读会话检查间隔，2–3600 秒 |
| `auto_reply.daily_limit` | 每日已验证自动回复上限，1–100 |
| `auto_reply.per_conversation_limit` | 单个会话每天允许的已验证自动回复上限，1–20 |
| `auto_reply.interval_seconds` | 两次已验证自动回复之间的最小间隔，1–3600 秒 |
| `auto_reply.stop_keywords` | 命中拒绝或停止联系文字时只记录、不回复 |
| `auto_reply.rules` | 由主面板话术库自动解析保存的关键词与已批准回复列表 |
| `candidate_filter.keywords` | 候选人关键词；多个词命中任意一个即可 |
| `candidate_filter.cities` | 候选人城市；多个城市命中任意一个即可 |
| `candidate_filter.salary_min_k` | 最低期望月薪，单位 K；`null` 表示不限制 |
| `candidate_filter.salary_max_k` | 最高期望月薪，单位 K；`null` 表示不限制 |
| `session_limit` | 本次启动流程最多邀约人数，1–200；可在主面板修改 |
| `daily_limit` | 每日沟通上限，验证成功和待人工核对都会占用名额；1–200，可在主面板修改 |
| `interval_seconds` | 每次成功发送后的等待秒数，1–3600；可在主面板修改 |
| `batch_size` | 每批成功发送数量；当前为 `20`，与默认每日上限一致 |
| `batch_pause_seconds` | 每批后的长暂停秒数；当前为 `0` |
| `max_consecutive_failures` | 连续失败停止阈值 |
| `include_keywords` | 包含关键词数组；空数组表示不限制 |
| `exclude_keywords` | 排除关键词数组；任意命中即跳过 |
| `match_mode` | `any` 命中任一，`all` 必须全部命中 |
| `risk_keywords` | 任意命中即截图并停止 |
| `desktop_window_title` | BOSS 主窗口标题，默认 `BOSS直聘` |
| `desktop_process_name` | 客户端进程名，默认 `boss-zhipin.exe` |
| `selectors` | UIA 控件类型、按钮文字和输入框提示词 |

关键词匹配忽略大小写和多余空格。请勿添加性别、民族、宗教、婚育等筛选条件。

面板中的“今日沟通”按候选人去重，包含已验证成功和“动作已发生但结果未知”的防重记录；“成功发送”只统计明确出现成功提示或“继续沟通”的记录；“待人工核对”是已点击但无法确认结果的人数；“当前未读消息”直接读取 BOSS 左侧“消息”未读数字，不会为了统计而打开或标记具体会话为已读；“今日回复”只统计通过消息出现且输入框清空双重验证的当前会话回复。点击“刷新统计”可手工刷新。

## 回复当前会话

本阶段采用保守流程，不会自动选择聊天对象：

1. 用户本人在 BOSS 客户端“消息”中打开需要回复的会话；
2. 在助手面板填写话术并点击“保存设置”；
3. 先保持 `dry_run=true`，点击“回复当前会话”检查是否能唯一识别聊天输入框和发送按钮；
4. 正式模式会显示完整话术和当前会话发送确认；确认后程序才会填写并点击“发送”；
5. 只有消息出现在聊天区且输入框清空，才记入“今日回复”。

如果输入框已有其他草稿，程序会取消操作，绝不覆盖。未验证的发送会记录为 `reply_unverified`、截图并暂停。程序使用消息页语义控件选择会话，不使用固定坐标猜测聊天对象。

## 全消息页未读自动回复

1. 在“自动回复话术库”中每行填写一条规则，例如：

   ```text
   可以|有兴趣|方便沟通 => 很高兴收到您的回复，请问明天下午方便面试吗？
   什么时候面试|面试时间 => 您好，请告诉我您方便的时间段。
   ```

2. 勾选“允许自动回复”，点击“保存设置”；
3. 点击“连接 BOSS 客户端”；
4. 点击“开启自动回复”。程序会自行进入消息页，每隔配置秒数扫描当前已加载的未读会话；
5. 先用未读列表的最新预览做保守匹配；预览未命中、同时命中多个不同回复或包含停止词时不打开、不发送；
6. 预览唯一命中后，程序精确打开该未读项，验证右侧会话对象，读取完整聊天，并在方向明确的对方消息中复核相同预览；
7. 对完整来信重新执行停止词与话术匹配，仍唯一命中才填写并点击明确的“发送”按钮；
8. 只有消息出现在聊天区且输入框清空才计入“今日回复”。

方向识别优先使用消息气泡的无障碍描述，例如“收到的消息/我发送的消息”；缺少语义时才使用气泡相对于聊天区域中线的左右位置。消息正文不会参与方向判定，避免对方用文字伪造发送方。语义和位置冲突、消息居中、没有命中话术或同时命中多个不同回复时均不自动发送。拒绝、不要联系或已找到工作等停止词优先于所有话术。

当前版本处理消息列表中已经加载且带明确未读数字的会话。若侧栏显示有未读，但程序无法可靠识别对应列表项，会截图并暂停，不会猜测点击。测试模式只匹配和记录：不会打开未读会话、不会填写、不会点击发送。

## 启用正式发送

只有完成多轮测试模式诊断后才考虑正式模式：

1. 关闭助手；
2. 手工编辑 `config.json`，将唯一的 `"dry_run": true` 改成 `false`；
3. 检查每日上限和岗位相关关键词；原生打招呼流程不会自动追加 `message`；
4. 重新启动并连接客户端；
5. 点击“开始/继续”时核对弹窗中的正式发送警告并人工确认。

正式发送前程序会再次检查测试模式、每日上限、去重记录、页面风险和明确的“打招呼”按钮。点击后只有出现“已向牛人发送招呼”，或同一候选人按钮变为“继续沟通”，才会记为 `sent`。程序不会查找聊天输入框，也不会追加第二条消息。点击动作已经发生但无法验证时会记为 `greeting_unverified`、截图、暂停并永久阻止该候选人自动重试；人工核对前不要继续。

## 暂停、停止和关闭

- “暂停”在当前不可中断的小操作完成后生效；所有计时等待可立即响应暂停或停止。
- “开始/继续”恢复处理。
- “停止”结束自动化工作线程并断开 UIA 连接，但不会强行关闭用户自己打开的 BOSS 客户端。
- 关闭助手窗口会请求停止并最多等待 5 秒，随后关闭短连接数据库生命周期。
- 单实例锁可防止同一目录重复启动两个助手。

## 数据、日志和截图

- 数据库：`data/boss_inviter.db`
- 日志：`logs/boss_inviter.log`，单文件 2 MB，最多保留 5 个轮转文件
- 截图：`screenshots/`

数据库表 `candidate_records` 包含：`candidate_key`、`candidate_name`、`candidate_url`（桌面客户端通常为空）、`candidate_summary`、`status`、`message`、`created_at`、`created_date`、`error_message`。只有 `sent` 计入每日发送数，并且数据库有候选人 `sent` 唯一索引。`reply_records` 单独记录 `reply_dry_run`、`reply_sent`、`reply_failed`、`reply_unverified` 和 `reply_skipped`；只有 `reply_sent` 计入“今日回复”。来信正文不写入数据库，只保存去重哈希、命中的话术名和实际回复内容。

## 常见故障

### 提示找不到 BOSS 客户端

确认客户端已启动、窗口标题是“BOSS直聘”，并且进程为 `boss-zhipin.exe`。不要让一个程序以管理员权限运行而另一个不是。

### 诊断显示 0 张候选人卡片

先确认已选择在线职位并进入“推荐”或“搜索”候选人结果。若客户端显示“暂无在线职位”，必须先在 BOSS 客户端内人工发布/选择职位。若页面确有候选人，开启 `diagnostics_save_tree` 后提供最新日志、诊断截图和脱敏 JSON。

### 找不到打招呼按钮或成功状态

BOSS 客户端可能改版。立即停止正式模式，切回 `dry_run: true`，运行页面诊断并按日志调整 `selectors.greeting_button_texts`、`selectors.continuation_button_texts` 或成功提示文字。不要用固定坐标补丁。

### 操作后状态无法验证

若点击前即失败，程序会记为 `failed`。若已经尝试点击但无法确认结果，程序会记为 `greeting_unverified`、截图并暂停，而且不会自动重试该候选人。请人工检查实际聊天窗口；未确认前不要继续。

若页面明确显示沟通权益不足、招呼次数用完或充值提示，程序会记录为 `failed` 并显示“平台权益不足，消息未发送”。这表示自动点击流程已经执行，但不代表候选人收到消息，也不计入今日沟通或成功发送。

### 配置错误

界面会显示中文校验错误，不会覆盖配置。可对照 `config.example.json` 修复 JSON 格式和字段类型。

## 页面/客户端改版处理

1. 立即保持或恢复 `dry_run: true`；
2. 打开目标候选人页并执行页面诊断；
3. 保存 `logs/boss_inviter.log`、最新诊断截图；
4. 如可接受，启用 `diagnostics_save_tree` 并提供已自动脱敏的 JSON；
5. 更新配置中的控件类型或文字后，仅在测试模式重新验证。

## 测试

离线测试不会连接真实 BOSS：

```powershell
python -m compileall .
python -m pytest
```

`tests/fixtures/mock_boss.html` 覆盖候选人卡片、沟通按钮、聊天输入框、发送按钮、下一页和风险提示；`tests/test_desktop.py` 使用假 UIA 控件树测试姓名识别、原生招呼成功提示、“继续沟通”状态、结果未知防重，以及为后续回复阶段保留的消息发送验证。

大批量流程演示不会连接 BOSS，也不会发送真实消息。它会模拟 100 人顺序处理、5 秒节奏、每日上限、第二轮防重复和结果未知暂停，并生成 HTML/JSON 证据：

```powershell
.\.venv\Scripts\python.exe main.py --batch-demo
```

结果位于 `reports/batch_demo.html` 和 `reports/batch_demo.json`。

## 打包与分享

双击 `build.bat`，或运行：

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --windowed --onedir --name BossInviter --additional-hooks-dir hooks --collect-submodules pywinauto --collect-all comtypes main.py
```

`build.bat` 会先跑测试，再生成目录版并复制可编辑配置，最终输出：

```text
dist/BossInviter-Setup.exe
dist/BossInviter-Windows-x64.zip
```

安装包和 ZIP 都不包含真实登录数据、SQLite 数据库、日志或历史截图。朋友可以直接运行安装包；如果使用 ZIP，则解压后运行 `BossInviter.exe`。首次使用必须保持测试模式。
